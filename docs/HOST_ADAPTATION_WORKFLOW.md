# 宿主适配标准流程

本流程用于从新 APK 入库到模块代码交付，也用于对全部历史样本补做兼容性核查。适用于 BIL，并通过功能契约、查询模板与验证门禁扩展到其它宿主。流程版本：1；整理日期：2026-10-21。

目标是让下一位开发者能够复现证据、发现遗漏、实现可维护的适配并准确说明交付范围。工具成功、找到类、生成报告、Hook 注册成功分别只是阶段证据，不能彼此替代。

## 1. 十分钟上手

1. 阅读目标项目的 AGENTS、README、适配器、功能安装器、构建与发布规则；记录当前工作树及用户授权范围。
2. 通过远程 MCP 取得 inventory，冻结准确样本列表。每个样本保存 `version_code + apk_sha256 + sample_revision`，同版本的不同构建分别登记。
3. 建立“功能 × 页面/协议路径 × 样本”的覆盖台账，从当前生产源码提取入口、访问器和兜底规则；历史报告只能补充线索。
4. 先用一个准确样本验证查询与结果大小，再通过 `plan_version_matrix` / `submit_version_matrix` 扩展到目标样本集。
5. 推进持久队列，分页收齐完整结果；把缺失、歧义、R8 形态变化逐项落到真实安装器和运行调用链。
6. 完成适配、接入适宜的 DexKit 语义兜底及回归；核查缓存结果确实被安装器消费。
7. 运行约定的软件门禁。若用户要求软件验收，按软件证据交付；设备与账号条件另列，不将编译冒充实测。
8. 复核差异，只提交有用源码、测试和维护文档；按仓库规则推送、创建 PR、合并并交付证据索引。

远程接入见 [REMOTE_README.md](../tools/hostlab/REMOTE_README.md)，准确 API、后端语义、分页与恢复规则见 [DEXSQL.md](../tools/hostlab/DEXSQL.md)。这些文档与当前 MCP schema 是运行参数的依据；本流程中的数量和示例不是永久服务限额。

## 2. 范围与身份先固定

### 2.1 任务清单

开工时记录以下信息，避免工作过程中不断扩大或误报范围：

| 项目 | 必填内容 |
| --- | --- |
| 目标 | 新版本、指定功能或全部存档样本；是否包含同版本不同构建 |
| 基线 | 当前生产提交、相邻兼容样本、签名谱系和已知行为 |
| 验收层级 | 静态/软件、Android 结构检查、实际 Hook 或设备 UI；各自是否要求 |
| 外部操作 | 查询、源码上传、APK 下载、设备安装、推送、合并、发布分别依据已有授权 |
| 环境 | 仓库规范、当前分支与未提交修改、工具与依赖版本、设备原状态（如使用） |
| 交付 | 代码范围、覆盖台账、测试记录、证据入口、PR、发布或恢复要求 |

普通远程 inventory/query/refs/decode 不要求把模块源码写入样本库。只读工具足够时直接使用；需要源码快照分析时，单独核对当前授权、目的地、载荷和源码新鲜度。不得把旧 published 快照当成当前工作树，也不为普通查询索要 HF 写令牌。

### 2.2 可复现身份

每条证据至少绑定：准确 APK SHA、不可变样本 revision、工具提交、请求摘要、后端版本、request/matrix ID、run/attempt、任务 ID、结果状态及完整性校验。模块结论另绑定源码提交或工作树指纹、适配规则代际与缓存 schema。

版本名不足以识别 APK。`file_id` 只在同一份数据集中有意义，跨版本比较以完整 descriptor、DEX provenance 和重复次数为准。不同签名谱系或不同变体不能默认为同一升级路径。

## 3. 用功能契约保证完整性

### 3.1 从生产调用链建立台账

从当前设置项、功能目录、安装器、定位器、运行访问器、协议转换器与资源入口交叉提取能力，不能只遍历固定类名表。逐项追踪：

```text
设置/依赖开关 → 页面/协议入口 → 候选发现 → 运行时契约复核
→ Hook 安装 → 回调实际触发 → 业务参数/结果修改
→ 本地或网络保存 → 读取/渲染 → 冷启动与异步刷新
```

每个功能列出全部适用路径：Java 与 Kotlin Moss、同步与回调/协程、原生 View 与 Compose、旧/新首页、主页面与子页面、缓存与网络。共用模型不代表共用入口；接口分派和反射调用不能仅凭静态引用排除。

建议维护下列可机读台账。格式可用 JSON/TSV，发布时可生成 Markdown；此模板是流程约定，不声称仓库已有自动执行器。

```json
{
  "feature_id": "player.codec",
  "path_id": "kotlin.unite.request",
  "sample": {"version_code": 9160200, "apk_sha256": "<完整SHA>", "sample_revision": "<不可变revision>"},
  "required": true,
  "applicability_reason": "该样本定义此播放请求家族",
  "contract_version": 1,
  "discovery": {"query_id": "<稳定任务ID>", "candidate_count": 1},
  "contract": {"status": "pass", "descriptor": "<完整方法描述符>", "checks": ["参数", "返回值", "修饰符", "序列化"]},
  "integration": {"consumer": "<真实安装器/访问器>", "status": "pass"},
  "evidence": [{"request_id": "<ID>", "run_id": "<run>", "task_id": "<task>", "status": "complete"}],
  "validation": {"static": "pass", "jvm": "pass", "android_structure": "not_run", "device": "out_of_scope"},
  "decision": "adapted_software",
  "remaining": []
}
```

台账状态至少区分：待查、已发现、契约通过、已接入、软件通过、运行通过、歧义、缺失、部分、失败、未收齐、合理不适用。`not_applicable` 必须附目标宿主不存在该路径等证据；可选能力也应说明适用性。不能用总体命中率掩盖任何必需路径缺口。

### 3.2 覆盖维度

至少审查评论、动态、首页、搜索、详情、影视、播放器、弹幕、Story、个人页及其它已启用功能；枚举协议家族时还需发现未登记的 Moss 调用者。对以下横切条件建立代表性回归：

- 总开关及下游开关依赖，默认值，关闭后不查询/不改写。
- 登录/未登录、会员/非会员、能力不足或服务端未下发的适用条件。
- 首次打开、保存、重复进入、冷启动、缓存命中/失效、异步目录刷新。
- 空值、空集合、未知模型、重复候选、错误泛型、反射失败与宿主异常。
- 模块共存、不同页面数据隔离、低版本路径与同名诱饵碰撞。

## 4. 云端取证与矩阵执行

### 4.1 推荐顺序

1. **盘点**：只读 inventory，冻结清单；不要把某次盘点的样本数量写死在工具里。
2. **预检**：`plan_analysis(request)` 校验请求；对一个准确样本 `submit_analysis` 验证字段、结果大小及语义。
3. **扩展**：`plan_version_matrix(samples, request)`，再 `submit_version_matrix`。按能力族分批，共用一次取样与后端会话。
4. **推进**：保存 matrix/request ID，调用 `advance_version_matrix` 补充持久队列。`version_matrix_status` 只观察，不会启动剩余作业。
5. **收集**：跟随 `version_matrix_result` 的 `next_offset` 收齐；大矩阵可在补满槽后有界预取，最后仍需默认模式的完整收集结论。
6. **验真**：核对逐样本、逐任务完成状态、摘要、页数、行数、字节边界和证据身份；物理 Actions 成功不能覆盖内部 partial/error。
7. **补缺**：只补缺失样本/任务/分片；变更查询时创建可区分的新请求，保留旧失败与分母。

当前单矩阵上限为 40 个准确样本，样本增长后确定性分片并登记联合覆盖范围。物理 runner 预算为 4；`execution_policy="adaptive"` 可改善共享环境成本，不能同时指定固定分组参数。具体上限及语义以当前工具文档为准。

示例请求（选择准确样本的参数在提交 API 中单独提供）：

```json
{
  "backend": "dexsql",
  "threads": 2,
  "timeout_seconds": 180,
  "tasks": [{
    "id": "entry_definition",
    "operation": "query",
    "dialect": "dexsql",
    "sql": "SELECT file_id,method_idx,method_descriptor FROM class_methods WHERE method_name='getUrlsMap' ORDER BY file_id,method_idx",
    "limit": 50,
    "pagination": {"max_pages": 8, "max_rows": 1000, "max_bytes": 1048576}
  }]
}
```

先验证这个入口对所查功能是否有意义，再复制模板；空结果只能说明该查询无匹配。

### 4.2 查询预算与分页

批量请求当前最多 16 项、30,000 UTF-8 字节；SQL 长度、任务结果、整个批次输出、页数和总时限分别受限。原生批量当前总输出为 2 MiB，单查询可声明至多 1 MiB；历史 1 MiB 批次和 typed/untyped 封装也会挤占末尾任务。提交前读取当前限制，不将请求文件大小等同于结果大小。

`limit` 是页大小。给外层 SELECT 明确 `ORDER BY`，投影唯一排序/消歧键，聚合内部也固定顺序。最多 32 页、10,000 行不意味着这些预算必然足够；检查 stop_reason、next_offset 和所有 truncation 标记。MCP 预览分页与 SQL 执行分页是不同层次：预览被截断时先读取已下载文件或续读结果，不重新扫描 APK。

字段较长时先测长度，只取需要列。超长布局可确定性聚合后按约 6,000 字符分块，块键包含样本、任务、owner、DEX 与连续序号；校验序号连续、累计长度和任务 complete，再拼接解析。不要制造超过单元格边界的巨大 JSON，也不要为每个字段重复全库扫描。

### 4.3 查询语义

- DexSQL 的 `class_methods/class_fields` 是定义，`methods/fields` 是引用；不能用引用证明类实际实现了方法。
- join 必须保留 `file_id` 及正确索引，不能跨 DEX 拼接同名字段或方法。保留重复定义并调查 ClassLoader 来源。
- `class_interfaces` 是直接实现关系，完整契约要遍历父类/父接口；可用声明 interface_count 与提取边数交叉核对。
- 调用表是静态引用，不自动解析虚调用最终目标。需要时沿实际调用者、被调用者及方法体追踪业务角色。
- `method_calls` 调用者列为 `method`、目标列为 `callee`；先读实际 schema，不能猜列名。别把 SQLite 方言不加区分地发送给 DexSQL。
- 泛型以原始 `dalvik.annotation.Signature` 为证据，按 file_id/annotation_off/owner、depth/ordinal 关联注解与字符串池，再拼接数组片段；JADX 推断仅作阅读辅助。
- 字符串、字段读写、类型消费者、资源与方法体相互印证。数字资源 ID 和 DEX 排序变化不能直接当作业务迁移。

官方表契约可查 [schema](https://dexsql.lsposed.org/docs/sql/schema) 与 [annotations](https://dexsql.lsposed.org/docs/sql/annotations)；本仓库固定版本及兼容差异仍以 [DEXSQL.md](../tools/hostlab/DEXSQL.md) 为准。

### 4.4 失败处理

| 状态 | 操作 |
| --- | --- |
| queued_local / in_progress | 推进原矩阵或观察，保留已有 ID；降低无变化轮询频率 |
| dispatch_unknown / status_unconfirmed | 只检查原 ID 与已知 run；不得换 key 重发或手改账本 |
| partial / 输出超限 | 找准停止任务和游标，缩减投影或确定性分片；只补未接纳内容 |
| 已封存可恢复查询 | 使用原 run/attempt/request、准确样本和显式 resume，复用已验真页面 |
| 已确认 failed/skipped | 按 `recover_version_matrix` 恢复规则显式重试；成功成员不重跑 |
| collection_errors | 重读同一页/附件，复用成功下载；收集失败不等于分析必须重跑 |
| 永久丢失附件 | 保留不可验收状态；只有明确选择允许的恢复策略才重新执行 |
| 查询写错或假设错误 | 保留旧失败，新任务验证修正；不能把查询错误解释成宿主入口不存在 |

不并发重复提交同样本的冷索引，不以重放未知派发提速。自动 AI 分析遵守自身请求、冷却、检查点和独立复核规则；AI 审查失败不得发布为完整成功报告，模型意见不能替代生产代码检查。

## 5. R8 必查项目

R8 不仅改短名，还会改类形态、继承、方法位置和调用约定。对所有路径统一执行下表，不只检查本次报错的功能。

| 变化 | 必须核对 | 实现原则 |
| --- | --- | --- |
| 类变接口/抽象基类 | 实际使用是虚读取、构造、Proxy 还是 Hook | 虚调用读取可接受合法抽象契约；Hook 方法仍要有可执行体；Proxy 才要求接口 |
| 实例方法静态化 | 完整参数、调用方、模型角色及 receiver 是否消失 | 从已核对参数恢复业务上下文；不继续用 receiver 判断页面 |
| 方法/字段/辅助类型改名 | 稳定业务模型、字符串、调用/字段关系 | 不穷举 a–z 或固定短名长度，不把辅助混淆名当主契约 |
| 内联、合并、桥接、合成闭包 | 真正产生效果的叶子方法及 bridge/synthetic 标记 | 外层 lambda 存在不代表持有可修改参数；定位实际单卡/结果入口 |
| 继承/接口迁移 | 声明成员与继承成员、完整父链、唯一实现 | 不仅查 declaredMethods，也不无条件放开所有父类成员 |
| 泛型擦除/类型别名 | Signature、构造器泛型、实际读写与 serializer | List/Map/Any 的擦除签名不足以判定业务模型 |
| Java/Kotlin 双通道 | 同步、异步、suspend、泛型回调的真实汇合点 | 各适用家族分别纳入分母；回调只透传时不要求其必须为接口 |
| Compose ABI | 模型、辅助参数、Modifier、Composer、flags/default masks 的位置 | 完整五/六参数等签名逐项验证；参数数量不能单独作为证据 |
| protobuf/序列化变化 | factory、builder、build、setter、clear、宿主格式及往返 | 使用已验证复制策略，保留未知字段和原对象的无变化身份 |
| 资源/页面重组 | 真实页面归属、资源名/类型、渲染与数据边界 | 有界定位与页面作用域；拒绝全局背景/颜色/数据修改 |

构造器、静态/实例、返回类型、参数、可见性、abstract/native、桥接、数组/原始类型、ClassLoader 均是契约的一部分。放宽某一条件前，先解释其在调用链中的作用，并增加正例与诱饵反例；不得统一删除 isInterface/isAbstract 检查。

## 6. DexKit 接入标准

优先顺序是稳定命名与类型快路径、指纹缓存、缺失时后台有界 DexKit。可稳定描述业务语义、且能在运行时唯一复核的路径，应接入 DexKit；名字已稳定且完整契约可靠的入口不为凑数量增加扫描。

合格查询需同时具备：

1. **范围**：明确宿主包/模块、候选与归档预算，不扫描所有进程或无限全库重试。
2. **语义**：稳定业务字符串/源码标记、特有模型、调用或字段关系，避免通用 boolean/List/JSON/Compose 形状匹配。
3. **完整 ABI**：声明/继承关系、参数位置、返回值、static/abstract、构造器与必要字段布局。
4. **唯一性**：先完整收集再唯一决策；零候选或多个合法候选返回未解决，不取 first() 碰运气。
5. **运行复核**：结果只是 descriptor；用真实宿主 ClassLoader 重新解析并校验，不信任缓存或扫描时类型假设。
6. **真实消费**：发现结果进入实际安装器与回调；只有写缓存没有注册或读取不算接入。
7. **生命周期**：开关关闭不查询，已解决不查询；共享现有桥接会话，在后台扫描，回调/绘制热路径不做 native 扫描。
8. **失败边界**：native 不可用、扫描未完成、指纹失配、候选歧义保留原行为，准确记为 unresolved/error。

缓存至少绑定宿主准确 APK/分包指纹与规则代际；规则变更与序列化 schema 变更分开管理。新增 JSON 键尽量可选，旧格式可解析，旧候选必须重新复核。负面尝试记录需区分“完成且无候选”与“扫描未完成”，按宿主/规则限制重试。

后台结果可安全补装时，注册必须幂等并可重试；共享 UI Hook 等只能冷启动消费的结果要明确说明生效时机，不重装整套 Hook 造成重复回调。输出可观察阶段：planned、resolved、installed、observed、applied、error，保持“找到”与“生效”的区分。

## 7. 业务修改与 UI 的额外检查

### 7.1 请求和模型改写

复制后修改，只替换目标字段；无变化返回原对象。验证 build/clear/setter 和继承签名，保留无关字段、回调与未知字段。Kotlin 不透明模型可通过宿主提供的 serializer 和 ProtoBuf 与已核对 Java wire 模型往返，必须验证双向类型与格式；旧四参数默认格式与新五参数调用方格式不能混用。失败放行原请求并限次记录错误。

过滤列表需检查 null、空集合、元素类型、重入、共享引用和业务上下文；避免原地污染其它页面。不要只看修改函数返回值，继续检查保存端、读取端和后台合并策略。

### 7.2 保存、重启、刷新链

对开屏选择等持久化能力，分别验证资格判断、选择、保存、下载完成、本地目录写入、上报、冷启动读取和后台刷新。保存成功不代表资源已下载；服务端列表与本地选择的交集为空可能触发清空。null 与空列表必须分别建例，同时覆盖关闭自定义模式、无已选素材、普通素材与其它授权类别。

用软件夹具模拟非会员条件可以证明分支和持久化策略；不能由会员账号操作推断真实非会员服务端行为。缺少指定账号或用户选择软件验收时，清楚记录证据层级，不修改账户权益或伪造实测结论。

### 7.3 引擎、模块与宿主归因

同样的左右滑动问题同时出现在引擎 sample 与模块时，先建立最小样例追踪事件分发和横纵手势仲裁；不能只在模块添加绕过。引擎修复后检查 sample 与消费者：横向切页、竖向滚动、斜向/边缘手势、开关点击、取消序列、回弹和重复切页。修改前后检查重要路径。

模块 UI 使用引擎标准选中样式、弹层进入/关闭动画和主题状态。总开关关闭时，下游无效设置应置灰并禁止点击、拖动和打开面板；重新启用后保留原值。仅有说明文字不等于依赖关系已正确表达。

## 8. 验证门禁与结论层级

| 层级 | 证明范围 | 不应推断 |
| --- | --- | --- |
| 云端静态 | 准确 APK 中的结构、注解、引用与方法体 | 实际 ClassLoader、服务器响应或 UI 已运行 |
| JVM 回归 | 对约定夹具的定位、拒绝、参数修改、缓存和失败行为 | 任意宿主所有分支都曾执行 |
| Android 结构检查 | 真 APK/真实运行类型的解析及契约（执行后才成立） | Hook 已触发或用户操作效果 |
| Hook 运行 | 安装、observed/applied/error 的真实记录 | 全页面、所有账号和服务端实验覆盖 |
| 设备 UI | 指定 APK/账号/设置与操作序列的观察结果 | 未测版本、非会员或其它灰度分组的效果 |

软件交付至少要求：所有适用必需路径完成结构与语义复核；对应生产消费者接入；新增正确性回归；Debug、必要测试 APK 编译、完整 JVM、Lint 和 Release R8 通过。按项目规则执行，不为低影响文案变化添加镜像测试，也不放宽既有基线或主分支发布保护。

BIL 可从 Gradle 项目目录运行：

```sh
./gradlew assembleDebug assembleDebugAndroidTest testDebugUnitTest :app:lintDebug :app:minifyReleaseWithR8 --console=plain --no-daemon
```

依赖已具备时才使用 `--offline`。编译 AndroidTest 只写“已编译”；实际执行才写“检查通过”。记录命令、源码提交、总数、失败/跳过与既有基线，避免反复重跑已完成且未受新变更影响的门禁。

必要回归应覆盖真实风险：R8 接口/抽象读取、长名称、泛型诱饵、重复合法候选、static receiver 消失、完整 Compose 参数写入、缓存失配、后台重复注册、四/五参数序列化、未知字段与身份保留、异常放行、null/空刷新。测试应经过实际安装器或访问器，避免只测试复制出来的查询逻辑。

## 9. 扩展约定

新增功能采用以下最小单元，复用已有会话、缓存和运行状态：

```text
FeatureSpec：功能ID、设置依赖、路径族、适用性、证据与完成标准
QuerySpec：任务ID、后端、语义范围、稳定排序、预算、输出契约
Contract：候选ABI、业务角色、唯一性与ClassLoader复核
Adapter：快路径/缓存/有界发现、合并与规则代际
Installer/Accessor：实际注册、读取或修改、幂等与失败放行
Verification：版本台账、正反例、真实消费者回归、验证层级
```

这些是可实现的接口边界，名称不要求与现有类一致。新增路径优先扩展功能目录与契约，不建立重复全局定位器。查询 ID 和输出字段保持稳定；破坏性变化升级契约版本并迁移缓存/台账。增加宿主版本时重用同一套契约矩阵，不复制一份“新版专用流程”。

建议后续自动化逐步加入：从设置和安装器生成覆盖差异、台账 schema 校验、候选唯一性及接口计数核对、每样本缺口汇总、只补缺失任务的计划生成、结果完整性检查与文档生成。自动化只能执行已定义规则，未映射的新家族必须进入待复核队列。

## 10. 交付与恢复

### 10.1 完成定义

- [ ] 当前生产源码的全部功能与适用路径已映射，样本清单冻结，同版本不同 APK 未合并漏算。
- [ ] 必需路径没有缺失、歧义、partial、未收齐或未接入项；不适用项有证据。
- [ ] R8 表中的形态变化已逐路径审查，查询结果接入实际运行消费者。
- [ ] DexKit 具有完整语义、唯一性、缓存复核、预算、开关依赖和失败放行。
- [ ] 云端逐任务 complete 与本地门禁成立，跳过项和结论层级清楚。
- [ ] 保存/重启/后台刷新、下游开关、旧路径回归已按功能风险检查。
- [ ] 重要文件修改前后复核，diff 无无关变更、秘密、原始 APK/DEX/索引/日志/基准数据。
- [ ] 依赖、引擎版本与缓存代际一致；保护分支规则保持有效。
- [ ] 已授权的推送/PR/合并/发布完成，记录最终提交及证据入口。
- [ ] 如曾改动设备，恢复原宿主版本、模块/漫游启用与作用域、账号和原有数据；清理自建测试包与临时副本。

任何必需路径未满足时，列出具体路径、样本、原因和下一动作；不能仅凭“类全部存在”或一个平均覆盖率声明全量适配。若用户约定软件交付，完成结论明确为软件范围，不附加未约定的设备验收阻塞。

### 10.2 最小交付文本

```text
范围：<功能/路径集合>；<准确样本数与revision>；<软件/设备层级>

限制：<未验证的账号/服务端/运行条件；不扩大结论>
交付：<合并提交、发布状态、回滚点、设备恢复结果（如适用）>
```

PR 描述围绕最终代码问题、结果和有效验证，删除探索噪声；原始证据在受控目录或云端分析记录中索引。不要把测试数据、APK、临时报告和源码快照混入产品提交。

## 11. 本轮经验与反例

2026-10-21 对 8.84.0～9.16.0 的 36 个准确 APK 完成了一轮软件核查；样本 revision 为 `16fbd5df9d99038f875564372172efddee76696c`。这是历史案例，后续必须重新读取 inventory。

| 发现 | 流程中的防线 |
| --- | --- |
| Story 策略基类变接口，另一个参数 getter 一直是抽象声明 | 分离虚读取、构造、Proxy 与 Hook 可执行体的契约 |
| 影视辅助类型改名，单卡方法迁入更深的 Compose 叶子 | 稳定模型/源码标记、全 ABI 与实际 Modifier 写入 |
| 首页分隔器改名，通用装饰器有同样 Paint/RectF 布局 | 结构之外检查 Lazy 字段、唯一候选及真实 drawLine/drawRoundRect 方法体 |
| Kotlin 播放请求类型改名且存在四/五参数家族 | 检查所有协议路径、宿主格式和双向序列化；透传回调不限定接口 |
| 搜索擦除后的 List 形状相同 | 原始 Signature、构造泛型、完整发现词对象图 |
| 合并函数/颜色助手静态化 | 参数角色和业务作用域取代 receiver 假设 |
| 已选开屏在后台 null 目录刷新后消失 | 选择→保存→下载→重启→刷新闭环与 null/空分开回归 |
| 多任务批次末尾超字节预算 | 按任务完整性检查，原矩阵保留、仅补缺失分片 |

该轮固定/生成候选及基础库检查取得 16,542 条类定义与 11,558 条去重直接接口关系，并补查全部搜索泛型与对象图；这些数量是证据规模，不等于逐页运行覆盖率。新增七项后台 DexKit 语义查询，最终软件门禁为 3816 项 JVM 测试（0 失败、0 错误、1 跳过）、Debug/测试 APK、完整 Lint 与 Release R8。复用经验时保留判定方法与反例，重新核对当前源码和样本，不能直接继承历史“通过”。
